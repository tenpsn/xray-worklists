# ระบบรายงานผล X-ray

ถ้าอยากรู้รายละเอียดเชิงเทคนิคลึกๆ โครงสร้างไฟล์ในระบบ, การเชื่อมต่อ DICOM ดูเพิ่มได้ที่ท้ายเอกสาร

## 1. เว็บทำอะไรให้บ้าง

เว็บนี้เป็น **ตัวกลาง** ที่คอยเชื่อมระหว่าง 2 ฝั่ง:

- ฝั่งซ้าย: ฐานข้อมูลของโรงพยาบาล HIS ที่มีรายชื่อคนไข้ที่ถูกส่งมาตรวจ X-ray
- ฝั่งขวา: เครื่อง X-ray ที่ต้องรู้ว่าวันนี้มีใครมาตรวจบ้าง

แทนที่เจ้าหน้าที่ต้องพิมพ์ชื่อ-นามสกุลคนไข้ที่หน้าเครื่องเองทุกครั้ง (เสี่ยงพิมพ์ผิด เสียเวลา) ระบบนี้จะดึงข้อมูลจาก HIS มาส่งให้เครื่องอัตโนมัติ

**สิ่งที่เว็บทำได้:**

- โชว์ตารางรายชื่อคนไข้ที่ถูกส่งตรวจ X-ray หน้าจอรีเฟรชเองทุก 10 วินาที
- กรอง/ค้นหาได้ เช่น ดูย้อนหลังกี่วัน, ดูเฉพาะรายการที่ยังไม่ยืนยันผล, ค้นหาชื่อรายการตรวจ
- สลับภาษาไทย อังกฤษ ได้ ชื่อคนไข้จะถูกแปลงเป็นตัวสะกดอังกฤษให้อัตโนมัติ
- ส่งข้อมูลคนไข้ไปให้เครื่อง X-ray
- พอตรวจเสร็จหรือยืนยันผลแล้ว ระบบจะเคลียร์รายการนั้นออกจากคิวของเครื่องให้เอง
- มีหน้า "ตั้งค่าระบบ" ให้กรอกข้อมูลการเชื่อมต่อฐานข้อมูล HIS และเครื่อง Modality ได้เองผ่านเว็บ

ระบบแบ่งเป็น 2 ส่วนที่ต้องรันพร้อมกัน:

- **Backend** (พอร์ต 4000) — ตัวที่คุยกับฐานข้อมูล HIS และคุยกับเครื่อง X-ray
- **Frontend** (พอร์ต 3000) — หน้าเว็บที่เราเปิดดูตาราง (ผ่านเบราว์เซอร์)

## 2. ของที่ต้องเตรียมก่อนติดตั้ง

1. เครื่องคอมพิวเตอร์ที่เป็น **Windows** และลง **Node.js** ไว้แล้ว (เวอร์ชัน 18 ขึ้นไป) — ถ้ายังไม่มีดาวน์โหลดได้จาก nodejs.org
2. รู้ข้อมูลเชื่อมต่อฐานข้อมูล HIS ของโรงพยาบาล ได้แก่ IP, Port, ชื่อฐานข้อมูล, Username, Password
3. ไฟล์ `dump2dcm.exe` (มากับโปรแกรม DCMTK) — เป็นตัวช่วยแปลงข้อมูลให้เป็นไฟล์ที่เครื่อง X-ray อ่านได้ **ไฟล์นี้ติดมากับโปรเจกต์อยู่แล้ว** ที่ `backend\dcmtk\bin\dump2dcm.exe` เว้นแต่ไฟล์นี้หายค่อยไปโหลดจาก dcmtk.org มาแทน
4. โปรแกรม **PM2** (ใช้ตอนขึ้นใช้งานจริง ให้ระบบรันค้างอยู่เบื้องหลังตลอด ไม่ต้องเปิดหน้าต่างค้างไว้) — จะติดตั้งตอนไหนก็ได้ ไม่จำเป็นต้องมีตั้งแต่ทดสอบครั้งแรก

## 3. ติดตั้งครั้งแรก (ทำทีละขั้น)

> เปิดโปรแกรม **Terminal / Command Prompt** ขึ้นมา แล้วพิมพ์คำสั่งตามทีละบรรทัด (กด Enter หลังพิมพ์แต่ละบรรทัด)

### ขั้นที่ 1 — วางไฟล์โปรเจกต์ให้ครบ

วางโฟลเดอร์ทั้งหมดไว้ที่ `D:\xray-worklists` (ถ้าจะวางที่อื่น ต้องไปแก้ path ในไฟล์ `start-system.bat` ให้ตรงด้วย) โครงสร้างควรมีหน้าตาแบบนี้:

```
xray-worklists/
├── backend/
├── frontend/
├── ecosystem.config.js
└── start-system.bat
```

### ขั้นที่ 2 — เช็คไฟล์ dump2dcm.exe

ไฟล์ `backend\dcmtk\bin\dump2dcm.exe` ติดมากับโปรเจกต์อยู่แล้ว แค่เปิดดูว่ามีไฟล์นี้อยู่จริง

ถ้าไฟล์นี้หายไป (เช่นก็อปปี้โปรเจกต์มาไม่ครบ) ค่อยไปดาวน์โหลด DCMTK เวอร์ชัน Windows binaries จาก [dcmtk.org](https://dcmtk.org) แตกไฟล์ zip ออกมาแล้วจะเจอ `dump2dcm.exe` อยู่ในโฟลเดอร์ `bin` ของมันอยู่แล้ว (ไม่ต้อง build เอง) ก็อปปี้ทั้งโฟลเดอร์ `bin` ไปทับที่ `backend\dcmtk\bin\`

### ขั้นที่ 3 — ติดตั้ง Backend

```bash
cd backend
npm install
copy .env.example .env
```

คำสั่งข้างบนนี้ทำอะไร:
- `npm install` = ติดตั้งโปรแกรมย่อยๆ ที่ backend ต้องใช้ (รอสักครู่จนเสร็จ)
- `copy .env.example .env` = ก็อปปี้ไฟล์ตั้งค่าตัวอย่าง มาเป็นไฟล์ตั้งค่าจริงของเรา

จากนั้นเปิดไฟล์ `backend\.env` ด้วยโปรแกรมแก้ไขข้อความ (เช่น Notepad) แล้วกรอกอย่างน้อย:
- `PORT=4000` (ปล่อยค่าเดิมได้เลย)
- `CORS_ORIGIN=http://localhost:3000` (ปล่อยค่าเดิมได้เลย ถ้า frontend รันที่เครื่องเดียวกัน)
- ค่าเชื่อมต่อฐานข้อมูล HIS เบื้องต้น — ใส่ได้ตรงนี้ หรือจะข้ามไปกรอกผ่านหน้าเว็บทีหลังก็ได้ (แนะนำ เพราะกรอกผ่านหน้าเว็บง่ายกว่า และแก้ได้ตลอดไม่ต้องมาเปิดไฟล์นี้อีก)

ทดลองรันดูว่า backend ทำงานได้ไหม:

```bash
npm run dev
```

เปิดเบราว์เซอร์ไปที่ `http://localhost:4000/health`

ตอนนี้ backend ยังไม่ได้ต่อฐานข้อมูลจริง (จะไปต่อในขั้นที่ 5) ดังนั้นจะเจอ 2 แบบ:
- ถ้ากรอกข้อมูล DB ใน `.env` ไว้แล้วและถูกต้อง → จะเห็น `{"ok":true,"db":"connected"}`
- ถ้ายังไม่ได้กรอก (หรือกรอกผิด) → จะเห็น `{"ok":false,"db":"disconnected", ...}` แทน **อันนี้ปกติ** แปลว่า backend รันสำเร็จแล้ว แค่ยังไม่ได้ต่อ DB ค่อยไปตั้งผ่านหน้าเว็บในขั้นที่ 5

### ขั้นที่ 4 — ติดตั้ง Frontend

เปิด Terminal อีกหน้าต่างหนึ่ง (หน้าต่างเดิมต้องปล่อยให้ backend รันค้างไว้):

```bash
cd frontend
npm install
```

ทดลองรัน:

```bash
npm run dev
```

เปิดเบราว์เซอร์ไปที่ `http://localhost:3000` — ถ้าเห็นหน้าตารางขึ้นมา (ต่อให้ยังว่างเปล่าหรือมี error เพราะยังไม่ได้ตั้งค่าฐานข้อมูล) แปลว่าเว็บใช้งานได้แล้ว ขั้นต่อไปคือกรอกข้อมูลเชื่อมต่อ

### ขั้นที่ 5 — กรอกข้อมูลเชื่อมต่อผ่านหน้าเว็บ

ที่มุมขวาบนของหน้าเว็บ กดเมนู **"ตั้งค่าระบบ"** แล้วกรอก 2 ส่วน:

1. **ฐานข้อมูล HIS** — เลือกชนิดฐานข้อมูล, IP, Port, ชื่อฐานข้อมูล, Username, Password
2. **การเชื่อมต่อเครื่อง Modality (MWL)** — AE Title, พอร์ตสำหรับให้เครื่อง X-ray ดึงรายชื่อคนไข้, พอร์ตสำหรับรับสถานะตรวจเสร็จ, และโฟลเดอร์เก็บไฟล์ที่จะส่งให้เครื่อง (ปกติใช้ค่า default คือ `backend/worklists` ได้เลย ไม่ต้องเปลี่ยน แต่ถ้าอยากเก็บไฟล์ไว้ที่อื่น เช่นไดรฟ์ที่แชร์กับเครื่อง Orthanc โดยตรง กดปุ่ม **"เลือกโฟลเดอร์..."** เดินดูโฟลเดอร์จริงบนเครื่องแล้วเลือกได้เลย — ถ้าเปลี่ยน อย่าลืมไปแก้ `Worklists.Database` ใน `orthanc.json` ให้ตรงกันด้วย ดูขั้นที่ 7)

กด **"บันทึกการตั้งค่า"** — ระบบจะทดสอบเชื่อมต่อฐานข้อมูลให้ทันทีและบอกผลว่าสำเร็จหรือไม่

### ขั้นที่ 6 — ตั้งค่าฝั่งเครื่อง X-ray

ไปที่เมนูตั้งค่าของเครื่อง X-ray เอง แล้วใส่ IP ของเครื่องคอมพิวเตอร์ที่รัน backend นี้อยู่ พร้อมพอร์ตและ AE Title ให้ตรงกับที่กรอกไว้ในขั้นที่ 5

### ขั้นที่ 7 — ตั้งค่า Orthanc

ระบบนี้ไม่ได้คุยกับเครื่อง X-ray โดยตรง แต่จะใช้โปรแกรมชื่อ **Orthanc** เป็นตัวคอยตอบเครื่อง X-ray โดยอ่านไฟล์ที่ backend สร้างไว้ ต้องเปิดไฟล์ตั้งค่า `orthanc.json` แล้วเช็ค 4 จุดนี้ (ปกติทำครั้งเดียวตอนติดตั้ง):

- **`StorageDirectory`, `IndexDirectory`** — โฟลเดอร์ที่มีอยู่จริงในเครื่อง (เช่น `D:\Orthanc`)
- **`Worklists.Database`** — ต้องเป็น**โฟลเดอร์เดียวกัน**กับที่ตั้งไว้ในขั้นที่ 5 (ค่าเริ่มต้นคือ `backend\worklists`) เช่น:
  ```json
  "Worklists" : {
    "Enable": true,
    "Database": "D:/xray-worklists/backend/worklists"
  }
  ```
- **`DicomAet`** — ต้องตรงกับ AE Title ที่กรอกไว้ในหน้าเว็บ Settings
- **`DicomPort`** — ต้องตรงกับ Port ที่กรอกไว้ในหน้าเว็บ Settings
- **`DicomAlwaysAllowFind`** — ถ้าตั้งเป็น `true` ให้ Orthanc ตอบเครื่องที่ถามมาได้เลย ไม่ต้องเพิ่มชื่อไว้ก่อน
- **`DicomAlwaysAllowFindWorklist`** — ถ้าตั้งเป็น `true` เหมือนข้อบนแต่เจาะจงเฉพาะการดึง Worklist (MWL)

> **`DicomAlwaysAllowFind` / `DicomAlwaysAllowFindWorklist` คืออะไร:** ปกติ Orthanc จะเช็คก่อนว่าเครื่องที่ถามมามีชื่อ (AE Title) อยู่ในรายชื่อ `DicomModalities` หรือยัง ถ้ายังไม่ได้เพิ่มเครื่อง X-ray ไว้ในรายชื่อนั้น จะถูกปฏิเสธไม่ตอบ ถ้าตั้ง 2 ค่านี้เป็น `true` ไว้ จะได้ไม่ต้องมาเพิ่มทีละเครื่อง (ค่าแรกคุมภาพรวม ค่าที่สองเจาะจงเฉพาะการดึงรายชื่อคนไข้/Worklist)

แก้เสร็จแล้วต้อง **restart โปรแกรม Orthanc** ค่าถึงจะมีผล

## 4. ใช้งานจริง — ให้ระบบรันค้างตลอดเวลา

ตอนทดสอบเราใช้ `npm run dev` ซึ่งพอปิดหน้าต่าง Terminal ระบบก็จะหยุดทำงาน วิธีที่ถูกต้องสำหรับใช้งานจริงคือให้ **PM2** ช่วยรันระบบอยู่เบื้องหลังตลอดเวลา

```bash
# สร้างไฟล์เว็บเวอร์ชันใช้งานจริงก่อน (ทำครั้งแรก และทุกครั้งที่มีการแก้โค้ด)
cd frontend
npm run build
cd ..

# ติดตั้ง pm2 (ทำครั้งเดียว ถ้ายังไม่เคยติดตั้ง)
npm install pm2

# สั่งรันทั้ง backend และ frontend พร้อมกัน
npx pm2 start ecosystem.config.js
```

เช็คว่าระบบรันอยู่ไหม:

```bash
npx pm2 status
```

ถ้าอยากดู log ว่าเกิดอะไรขึ้นบ้าง:

```bash
npx pm2 logs xray-backend
npx pm2 logs xray-frontend
```

### ให้ระบบรันเองอัตโนมัติด้วย start-system.bat

แทนที่จะพิมพ์คำสั่งข้างบนทุกครั้ง มีไฟล์ **`start-system.bat`** เตรียมไว้ให้แล้วที่ทำงานเดียวกัน (สั่ง `pm2 start ecosystem.config.js` ให้อัตโนมัติ)

**ต้องวางไว้ตรงไหน:** ไฟล์นี้ต้องอยู่ที่ root ของโปรเจกต์ (ที่เดียวกับ `ecosystem.config.js`) คือ `D:\xray-worklists\start-system.bat` — ถ้าทำตามขั้นที่ 1 มาปกติ ไฟล์นี้จะอยู่ตรงนั้นอยู่แล้ว ไม่ต้องย้ายไปไหน (ถ้าวางโปรเจกต์ไว้ที่อื่นไม่ใช่ `D:\xray-worklists` ต้องเปิดไฟล์นี้ด้วย Notepad แล้วแก้บรรทัด `cd /d "D:\xray-worklists"` ให้ตรงกับตำแหน่งจริงก่อน)

**วิธีใช้ครั้งแรก (รันด้วยมือ):** ดับเบิลคลิกไฟล์ `start-system.bat` ได้เลย จะมีหน้าต่างดำๆ (cmd) เด้งขึ้นมาแป๊บหนึ่งแล้วปิดไปเอง — ปิดไปได้เลยไม่มีผลอะไร เพราะ pm2 จะรันระบบอยู่เบื้องหลังต่อ (เช็คด้วย `npx pm2 status` ได้ว่ารันอยู่จริง)

**วิธีตั้งให้รันอัตโนมัติทุกครั้งที่เปิดเครื่อง Windows (ผ่าน Task Scheduler):**

1. กด Start แล้วพิมพ์ค้นหา "Task Scheduler" เปิดขึ้นมา
2. คลิกขวาที่ "Task Scheduler Library" (หรือมุมขวา) เลือก **Create Task...**
3. แท็บ **General**: ตั้งชื่องาน เช่น `Start Xray Worklists`
4. แท็บ **Triggers**: กด New... เลือก Begin the task เป็น **At startup** (รันตอนเปิดเครื่อง)
5. แท็บ **Actions**: กด New... เลือก Action เป็น **Start a program** แล้วกด Browse ไปเลือกไฟล์ `D:\xray-worklists\start-system.bat`
6. กด OK จนครบทุกแท็บ

**อีกวิธี (ง่ายกว่า) — วาง shortcut ไว้ในโฟลเดอร์ Startup:**

1. กด `Win + R` พิมพ์ `shell:startup` แล้ว Enter (จะเปิดโฟลเดอร์ Startup ของ user ที่ login อยู่)
2. คลิกขวาไฟล์ `D:\xray-worklists\start-system.bat` เลือก **Show more options > Send to > Desktop (create shortcut)** จะได้ shortcut ของไฟล์นี้บน Desktop
3. ลาก shortcut ที่ได้ไปวางในโฟลเดอร์ Startup ที่เปิดไว้ในขั้นที่ 1

**ต่างกับ Task Scheduler ยังไง:** วิธีนี้จะรันก็ต่อเมื่อมีคน **login** เข้า Windows แล้วเท่านั้น (ถ้าตั้ง auto-login ไว้ หรือมีคน login เข้าประจำทุกครั้งที่เปิดเครื่อง ใช้วิธีนี้ได้เลย ตั้งง่ายกว่า) ส่วน Task Scheduler ตั้งเป็น "Run whether user is logged on or not" ได้ ทำให้รันตอนบูตเครื่องได้เลยแม้ไม่มีใคร login เข้าเครื่องเลย — เหมาะกว่าถ้าเครื่องนี้ไฟดับแล้วรีสตาร์ทเองบ่อยๆ โดยไม่มีคนอยู่หน้าเครื่องคอยกด login

## 5. คำถามที่พบบ่อย

**เปิดเว็บแล้วตารางว่างเปล่า/ขึ้น error ทำไง?**
เช็คหน้า "ตั้งค่าระบบ" ว่ากรอกข้อมูลฐานข้อมูล HIS ถูกไหม (IP, Password) แล้วลองเข้า `http://localhost:4000/health` ดู — ถ้าเห็น `"ok":true,"db":"connected"` แปลว่าต่อ DB ได้แล้ว ถ้ายังเห็น `"db":"disconnected"` แปลว่า IP/Password/Port ที่กรอกไว้ยังไม่ถูก ให้กลับไปแก้ในหน้า Settings อีกที

**เครื่อง X-ray ไม่เห็นรายชื่อคนไข้?**
เช็คว่าไฟล์ `dump2dcm.exe` มีอยู่จริงตาม path ที่กำหนด และเช็คว่า Orthanc ตั้งค่าโฟลเดอร์ `Worklists.Database` ตรงกับโฟลเดอร์ที่ backend ใช้จริงหรือไม่ (ดูขั้นที่ 7)

**ต้องไปยืนยันผล X-ray ที่เว็บนี้ไหม?**
ไม่ต้อง ระบบนี้แค่โชว์ตารางให้ดู การยืนยันผลยังทำผ่านระบบ HIS ตามเดิม

## 6. รายละเอียดเชิงเทคนิค

ส่วนนี้อธิบายเจาะลึกว่าระบบสร้าง/แก้ไข/ลบไฟล์อะไรบ้างในเครื่อง server และไฟล์แต่ละไฟล์ในโค้ดทำหน้าที่อะไร เผื่อดูแล-แก้ไขต่อในอนาคต

### ไฟล์และข้อมูลที่ระบบสร้าง/แก้ไข/ลบเองอัตโนมัติ

ระบบไม่แตะฐานข้อมูล HIS โดยตรง แต่จะจัดการไฟล์บนเครื่อง backend เองดังนี้:

**โฟลเดอร์ `backend/worklists/`**

- **`<XN>.dump`** — เกิดขึ้น: สร้างชั่วคราวเมื่อมีเคสใหม่/ข้อมูลเปลี่ยน เพื่อรอแปลงเป็น `.wl` / ถูกลบ: ลบทันทีหลังแปลงสำเร็จ (ถ้าไฟล์ล็อกอยู่ ลองซ้ำสูงสุด 3 ครั้ง)
- **`<XN>.wl`** — เกิดขึ้น: สร้าง/อัปเดตด้วย `dump2dcm` เมื่อข้อมูลเปลี่ยนจากครั้งก่อน (เทียบด้วย hash) / ถูกลบ: ลบเมื่อยืนยันผลครบทั้งคู่ (`confirm`+`confirm_read_film`=Y) หรือเครื่องส่ง MPPS `COMPLETED`/`DISCONTINUED`
- **`.worklist-state.json`** — เกิดขึ้น: เก็บ hash + StudyInstanceUID ของแต่ละ XN กันสุ่ม UID ซ้ำ / ถูกลบ: ลบ entry ของ XN นั้นเมื่อ `.wl` ถูกลบ (ไฟล์นี้เองไม่ถูกลบทั้งไฟล์)

**โฟลเดอร์ `backend/logs/`** เก็บไฟล์ `dicom-network-YYYY-MM-DD.log` วันละไฟล์ (log การเชื่อมต่อ DICOM/MPPS) ลบอัตโนมัติเมื่ออายุเกิน 7 วัน

**`backend/mpps-state.json`** 
    เก็บ mapping SOP Instance UID ↔ Accession Number (XN) ที่เครื่อง Modality ส่ง N-CREATE เข้ามา เพื่อจับคู่ตอนได้รับ N-SET ทีหลัง ลบ entry ทันทีเมื่อได้รับสถานะ `COMPLETED`/`DISCONTINUED`

**`backend/settings.json`** 
    เก็บค่าที่ตั้งจากหน้า "ตั้งค่าระบบ" (แทนที่ค่าจาก `.env`) รหัสผ่านจะไม่ถูกส่งกลับไปแสดงที่หน้าเว็บ (ปิดบังด้วย `••••••••` เสมอ) และจะไม่ถูกเขียนทับด้วยค่าว่างโดยไม่ตั้งใจตอนกดบันทึก

### ไฟล์หลักในโค้ด ทำหน้าที่อะไร

**Backend**

- **`server.js`** — จุดเริ่มต้นของ backend เปิด API ให้ frontend เรียก, ดึงข้อมูลจาก HIS DB, สั่งสร้างไฟล์ worklist
- **`db.js`** — เชื่อมต่อฐานข้อมูล รองรับทั้ง Postgres และ MySQL สลับกันได้ตาม Settings (จัดการ encoding ไทยให้ด้วย)
- **`dicomService.js`** — แปลงข้อมูลคนไข้เป็นไฟล์ `.wl` (แปลงชื่อไทยเป็นคาราโอเกะถ้าเลือกอังกฤษ) ใช้ `dump2dcm.exe` แปลง `.dump` เป็น `.wl`
- **`mppsService.js`** — เปิด server แยก (พอร์ต 7001) รับสถานะ "เริ่มตรวจ"/"ตรวจเสร็จ" จากเครื่อง Modality แล้วลบไฟล์ worklist เมื่อเสร็จ
- **`hl7Service.js`** — (ทางเลือก) ถ้าเปิดโหมด HL7 จะรับข้อความจากระบบอื่นแทนการดึง DB โดยตรง แล้วแปลงเป็น worklist เหมือนกัน
- **`settingsService.js`** — โหลด/บันทึกการตั้งค่า HIS DB และ MWL ลงไฟล์ `settings.json`

**Frontend**

- **`app/page.js`** — หน้าหลัก แสดงตาราง X-ray, กรอง/ค้นหาได้, auto-refresh ทุก 10 วิ, สลับภาษาไทย/อังกฤษ
- **`app/settings/page.js`** — หน้าตั้งค่า HIS DB (host, port, username, password, encoding) และ MWL (AE Title, port)
- **`app/lib/nameDisplay.js`** — จัดรูปแบบชื่อ-นามสกุลที่แสดงในตาราง ตัดความยาว, แปลงเป็นคาราโอเกะเมื่อเลือกอังกฤษ

### เลือกโฟลเดอร์เก็บไฟล์ Worklist

ปกติไฟล์ `.wl` จะถูกเก็บในโฟลเดอร์ `backend/worklists` แต่ถ้าอยากให้อยู่นอก backend เช่นอยู่บนไดรฟ์ที่แชร์กับเครื่อง Orthanc โดยตรง ในหน้า Settings มีปุ่ม **"เลือกโฟลเดอร์..."** ให้เปิดหน้าต่างเดินดูโฟลเดอร์จริงบนเครื่อง backend ได้เลย เปลี่ยนได้ตลอดเวลาโดยไม่ต้อง restart backend — แต่**ต้องไปแก้ `Worklists.Database` ใน `orthanc.json` ให้ชี้ตำแหน่งเดียวกันด้วยเสมอ** ไม่งั้นเครื่อง Modality จะหาไฟล์ไม่เจอ

### ความทนทานต่อ error (Reliability)

- **`max_memory_restart`** ใน `ecosystem.config.js` — ถ้า backend กินแรมเกิน 300M หรือ frontend เกิน 400M PM2 จะสั่ง restart process นั้นให้อัตโนมัติ
- **Uncaught exception / unhandled rejection** — ถ้าเกิด error ที่ไม่ได้ดักไว้ ระบบจะ log แล้วปิดโปรแกรมทันที (`process.exit(1)`) แทนที่จะทำงานต่อในสภาพ state เพี้ยน แล้วปล่อยให้ PM2 (`autorestart: true`) เริ่ม process ใหม่แบบสะอาด
- **Port ชนกัน** — ถ้า backend เปิดไม่สำเร็จเพราะมีโปรแกรมอื่นใช้ port นั้นอยู่แล้ว ระบบจะปิดโปรแกรมทันทีพร้อม log ชัดเจน ส่วน MPPS server ถ้าเปิดไม่สำเร็จตอนสตาร์ทเครื่องถือว่าร้ายแรงและปิดโปรแกรมเช่นกัน แต่ถ้าเปลี่ยน MPPS port จากหน้าเว็บ Settings แล้วเปิดไม่สำเร็จ จะแค่แจ้งเตือน ไม่ปิดทั้งระบบ
- **`GET /health`** ทดสอบเชื่อมต่อฐานข้อมูลจริงด้วย (`SELECT 1`) ไม่ใช่แค่เช็คว่า process ยังไม่ตาย — ถ้าต่อ DB ไม่ได้จะตอบ HTTP `503` เหมาะสำหรับให้เครื่องมือ monitor ภายนอกเรียกเช็คเป็นระยะ

### หมายเหตุอื่นๆ

- ระบบไม่แก้ไข/ลบข้อมูลใดๆ ในฐานข้อมูล HIS โดยตรง การยืนยันผล/อ่านฟิล์ม ยังคงทำผ่านระบบ HIS ตามปกติ
- การแปลงชื่อไทยเป็นภาษาอังกฤษ (คาราโอเกะ) ใช้เฉพาะแสดงผลและใส่ในไฟล์ worklist เท่านั้น ไม่กระทบข้อมูลจริงในฐานข้อมูล
- `dump2dcm.exe` ต้องมีอยู่จริงตาม path ที่กำหนด มิฉะนั้นระบบจะสร้างได้แค่ไฟล์ `.dump` (เครื่อง Modality จะยังไม่เห็นรายการ เพราะต้องเป็นไฟล์ `.wl` เท่านั้น)
- path ของ `dump2dcm.exe` ปัจจุบันเขียนแบบ Windows เท่านั้น ต้องรันบนเครื่อง Windows หรือแก้ path ในโค้ดถ้าจะรันบน Linux/Mac
